# Stockage local : décision et qualification

Décision technique candidate : SQLCipher embarqué dans `packages/local-store` via `rusqlite 0.41.1` et la fonctionnalité `bundled-sqlcipher-vendored-openssl`. Le desktop Tauri 2 dépend directement de cette bibliothèque Rust. Aucun plugin SQL, accès fichiers général ou commande de base n’est exposé au JavaScript. SQLite standard ne chiffre pas ; il n’existe aucun repli en clair.

La compatibilité repose sur une bibliothèque native compilée pour chaque cible, indépendante du protocole des plugins Tauri. Elle doit être démontrée par compilation et tests Windows/macOS, puis par validation des applications signées. Une exécution Linux ne vaut pas qualification Windows/macOS. La porte publique `PLATFORM_STORAGE_VALIDATED = false` refuse l’ouverture avant toute création de fichier ou de clé. Les fonctions internes sont privées ; les tests internes peuvent les éprouver sans ouvrir la porte de l’application. Ne pas retirer cette porte à la seule lecture de ce document.

Une clé aléatoire de 256 bits provient du générateur du système ; elle n’est jamais dérivée d’un identifiant, codée en dur ou enregistrée dans `.env`. SQLCipher reçoit une clé brute. Les chaînes temporaires de clé sont effacées avec `zeroize` lorsque possible. La mémoire d’un processus compromis ne peut pas être garantie par ce mécanisme.

`keyring 3.6.3` utilise Windows Credential Manager (`windows-native`) ou le trousseau macOS (`apple-native`). Chaque clé est liée à l’entreprise, l’utilisateur et l’appareil. Le test natif inclut un aller-retour réel dans le magasin du système. Aucune clé de secours en fichier n’est fournie. Une clé manquante pour un fichier existant provoque un refus, sans remplacement ou destruction silencieuse. La récupération et la rotation des clés restent à concevoir avant l’activation : les brouillons ne remplacent jamais un enregistrement financier central.

L’ouverture vérifie `cipher_version`, configure la clé, puis vérifie réellement la lecture avant d’écrire. Les erreurs sont génériques. Le journal rollback est chiffré par SQLCipher, les fichiers temporaires sont en mémoire, la protection mémoire SQLCipher est activée et le fichier est créé avec des droits Unix 0600 lorsque disponibles. Les liens symboliques sont refusés à l’ouverture. La base est liée à un périmètre unique. Les migrations transactionnelles refusent les versions inconnues. Les montants sont des chaînes décimales canoniques.

L’autorisation hors connexion expire au plus après quinze minutes. Une horloge monotone empêche de prolonger une session ouverte en reculant l’horloge système ; le renouvellement d’une autorisation à l’ouverture devra être fourni par la session serveur future. Les brouillons portent UUID, révision, état, création et expiration ; le cache porte version de schéma, version de données, date de synchronisation et expiration d’autorisation. La base locale ne possède aucun grand livre ni table de solde officiel.

L’effacement supprime la clé du magasin puis le fichier fermé. La suppression physique irréversible sur SSD, snapshots, sauvegardes ou copies antérieures n’est pas garantie ; la destruction de la clé constitue la mesure principale. Le magasin natif et le profil OS doivent aussi être protégés. Les événements de déconnexion, révocation, changement de périmètre et compromission doivent être raccordés à cette procédure avant activation.

À qualifier avant activation : compilation et tests sur les deux OS, permissions/ACL du fichier Windows, conditions du trousseau macOS pour une application signée, réouverture après redémarrage, refus après verrouillage/révocation, comportement pendant interruption de migration, installateurs signés et mises à jour, stratégie de rotation/récupération et maintenance des versions SQLCipher/OpenSSL. Les licences et obligations de redistribution doivent être revues ; aucune qualification FIPS ou conformité réglementaire n’est revendiquée.

Sources techniques à consulter lors de la qualification : [rusqlite](https://docs.rs/rusqlite/0.41.1/rusqlite/), [SQLCipher](https://www.zetetic.net/sqlcipher/), [keyring](https://docs.rs/keyring/3.6.3/keyring/), [prérequis Tauri](https://v2.tauri.app/start/prerequisites/). Les versions transitives réellement utilisées sont celles des deux `Cargo.lock`.
